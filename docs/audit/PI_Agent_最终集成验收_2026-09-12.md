## 4. 本次审计发现并修复的问题

### 4.1 Mutation post-commit finalization 一致性

原行为：`MutationWriteGateway.transaction()` 已成功提交并完成 reread verify 后，如果 Proposal `COMMITTED` 状态持久化或 COMMITTED Audit 失败，会进入统一 catch，将 Proposal 改成 `FAILED`。

风险：业务数据库已经完成写入，但控制面显示 FAILED，用户/上层可能误判并重试；Approval nonce 已经在同一事务内消费，形成“业务事实成功、控制面失败”的双重事实。

修复：

1. 将“业务事务执行”与“提交后 finalization”拆成两个错误域；
2. 事务真正失败时才允许 Proposal 进入 FAILED；
3. `MUTATION_APPROVAL_REPLAYED` 不再触发 FAILED 状态写入；
4. 业务事务成功后先写 COMMITTED Audit，再将 Proposal 更新为 COMMITTED；
5. post-commit Audit/Proposal finalization 失败时返回 `MUTATION_COMMIT_FINALIZATION_FAILED`，明确业务写已提交并验证、禁止自动重试、需要按 `operationId` 对账；
6. 新增回归测试模拟 Proposal COMMITTED 持久化故障，验证业务记录已改变、COMMITTED Audit 已存在、Proposal 不会被误标 FAILED、token replay 不会进一步污染状态。

剩余生产要求：Proposal/Audit 与业务写若落在不同持久化边界，生产环境仍应提供 durable outbox 或 reconciliation job，使“已提交但 finalization 待修复”能够自动收敛，而不是仅依赖进程内 Trace。

### 4.2 MySQL README 迁移清单过期

实际 migration/rollback 已到 007，但 `db/mysql/README.md` 仍只列 001–004。本次同步补齐 005 Mutation、006 RAG、007 Audit Policy 以及完整的正向/反向顺序。SQL 文件本身未修改、未执行。

## 5. 安全边界审查

### Request/Scope

- READ Tool 的 tenant/user/company/project 由服务器 RequestContext 提供；Tool args 使用严格字段白名单，Scope 注入会因未知字段或 mismatch 被拒绝。
- Working Memory 以 tenant/user/company/conversation 隔离；显式 RequestContext project 优先，项目切换会清理旧项目绑定槽位。
- M9 Entity Resolver、RAG ACL、Report Dataset/Evidence、M12 Schema/Broker 都重新验证 server scope。

### Write boundary

- Agent Tool 只有 `prepare_create/update/delete` 和 `commit_mutation`；commit 为 CRITICAL + requiresConfirmation。
- Approval Token 绑定 nonce、operation/digest/version/user/tenant/company/project，并在事务中一次性消费。
- M10 自主 Loop 会阻断 CRITICAL、requiresConfirmation 以及非 dry-run 的写 Tool。
- M9 图片输入和 M12 分析最多进入 prepare，不持有 approve/commit 能力。

### RAG

- ACL/visibility 在召回之前构造为 backend access filter；服务层仍对返回候选做 defensive recheck。
- 无证据时不调用生成器强答。
- Citation 保存 document/chunk/page/section/source/parser/chunker/embedding/index version。

### Sandbox

- SQL 静态层仅接受受限 `SELECT/WITH SELECT`；生产 Broker 仍必须二次执行 read-only、server scope、schema allowlist、timeout 和 query-cost guard。
- Python 仅能通过固定 queryId 的 `read()` 能力取数；无 DB credential/client、网络、文件系统、进程或动态代码能力。
- 真实隔离效果依赖生产 Sandbox Executor，当前代码中的 Runtime Attestation 是契约，不是已完成的基础设施证明。
